## 二、定位：不跟引擎比算力，比"人"

继续讲"六档难度""双引擎架构"是**打不赢 Pikafish 的**——那本来就是它的引擎，2.1k star 摆在那里。

我们的故事只有一个：

> **全世界第一个认真为长辈设计的中文象棋应用。**

这个定位的三个支点，全部是现有功能：

| 支点 | 具体证据（已实现，不是 PPT） |
|---|---|
| 看得清 | 正文 ≥19px、按钮 ≥56px、浅色高对比 |
| 听得懂 | 不出现"深度/节点/NPS/评估分"，只说"这局你赢了""这步该走炮二平五" |
| 下得动 | 连赢 3 局自动升档、连输降档，永远匹配得上水平 |

这三条在开源圈有专门的语境：**accessibility（无障碍/适老）**。这是国际开发者会认真对待、会给 star 的议题，而不是"又一个象棋 demo"。

**已落地范围**：

| 位置 | 取值 | 说明 |
|---|---|---|
| GitHub description / README | 老将 · Laojiang | 中英双语首屏 |
| 产品 `<title>` | 老将 · 中国象棋 | 保留关键词便于浏览器标签识别 |

> **仓库名保持 `xiangqi-elder` 不改**。原因：改 repo 名会连带 Pages 地址变成

## 四、仓库描述（Description）

GitHub description 上限 350 字符，同时被 GitHub 搜索和 Google 索引。公式：**是什么 + 给谁用 + 有什么 +（英文兜底）**。

### 推荐版本

```
给家里的老将：无广告的中国象棋。字大、按钮大、只说人话。会记战绩、自动调难度、下完告诉你哪一步该改。
A clean, ad-free Xiangqi (Chinese Chess) for elderly players — big UI, plain language, no chess jargon.
```

**埋进去的关键词**：中国象棋、Xiangqi、Chinese Chess、无广告、ad-free、elderly、适老。
中文段打国内搜索，英文段打国际搜索和 Google。

### 备选（更短，记忆点优先）

```
给爸爸一个干净好用的象棋伴侣：无广告、会记战绩、难度跟着你变、下完有教练点评。 Ad-free Xiangqi for elderly players.
```

## 六、README 改造

### 现状问题

1. **首屏没有英文**——国际访客 3 秒内离开
2. **首屏没有截图**——纯文字，看不出"适老"到底长什么样（这是最大损失）
3. 没有徽章（license / stars / demo），少了可信度信号
4. "技术说明"占了大量篇幅，而这不是本项目的卖点

### 改造结构（新首屏）

```

> 给家里的老将，一个干净的棋盘

[中文] [English] [在线试玩] [License: GPL-3.0]

字大、按钮大、只说人话——不说"深度/节点/NPS"，只说"这局你赢了"。

三个数字（比形容词有力）：
  · 19px   正文字号（一般 App 是 14px）
  · 56px   按钮高度（拇指友好）

（对比表保留，这是全文最有说服力的部分）

## 试一试
（两个链接 + 加桌面引导）

## 技术细节
（现有内容收到这里，折叠或下移）
```

## 八、一个会拖后腿的硬伤

**49MB 的 NNUE 权重直接躺在仓库里。**

后果：任何人 `git clone` 都要拉 49MB。对一个"看起来只是个小网页"的项目，这会让一部分本来想 star 的人直接关掉页面。

三个选项：

| 方案 | 做法 | 权衡 |
|---|---|---|
| **A. 保持现状** | 不变 | 最省事，clone 慢 |
| **B. 首次运行时下载** | 权重不进仓库，由应用在用户选 4~6 档时才 fetch | 仓库降到 <2MB，clone 秒下。已有缓存逻辑，改动小。**推荐** |
| **C. Git LFS** | 权重走 LFS | **不行**——Pages 不会展开 LFS 指针，线上会拿到文本指针而不是二进制 |

**建议**：短期先做 A（不阻塞），等要正式推广前切 B。

## 九、上架到 WorkBuddy

WorkBuddy 有三条"上架"路径，性质完全不同：

| 路径 | 状态 | 说明 |
|---|---|---|
| **① 发布为应用**（sites） | ✅ **已完成** | 已有分享链接 `xiangqi-elder.app.workbuddy.host`，在「设置—数据管理—应用」里管理。这是"能用"，不算"上架" |
| **② 社区作品**（灵感社区） | ⏳ 可做 | 创建作品 → 进待审 → 审核通过后公开可见，其他 WorkBuddy 用户能发现。**这才是真正意义上的"上架"** |
| **③ 打包成 Skill / 专家** | ⏳ 可选 | 把这个项目封装成"一键生成适老应用"的 Skill，属于另一个产品（工具而非应用），不建议混在一起 |

**②的具体做法**：上传封面图 + 预览图 → 填标题/副标/描述（中英双语）→ 主产物指向在线链接 → 提交待审。

**注意**：社区作品审核看的是"作品完整度"，需要**封面图**。目前项目只有 PWA 图标，没有宣传图，需要补一张（手机截图 + 项目名）。

## 附：预期与预期管理

一个诚实的判断：

- 做完 1–5，**不会**自然涨到几百 star。GitHub 站内没有"新项目推荐"机制。
- 真正的变量是**阶段 2 那一篇文章写得怎么样**。同类项目 `ryukeilee/xiangqi`（单文件版）有 2 star，`XMuli/ChineseChess`（Qt 桌面版，功能更全）有 832 star——差距不在代码质量，在**有没有人知道它**。
- 本项目最可能起量的角度是**"适老/无障碍"**而不是"象棋"：象棋赛道头部已经被引擎占死，而 a11y 赛道几乎没人做中文棋类。

所以我把资源押在：**把"为长辈设计"这件事讲透**，而不是继续堆功能。
