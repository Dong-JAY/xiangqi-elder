4 个答案里最值得说的：成长感 ≠ 隐藏数据

v1 我主张"把所有引擎数据折叠进详情页"。这对技术参数是对的（深度/节点/NPS 对爸爸无意义），但如果连进步本身也藏起来，就没有成长感了。

正确的切分是：

该藏该露
深度、节点数、NPS、厘分损失连胜几场、难度升到第几档、和上个月比进步了多少
"score cp -35""这步应该先跳马"
引擎内部思考过程"你上盘这步就对了，这次换了个思路也一样对"

核心原则：藏术语，露进步。

2. 成长感系统（新增，v1 没有）

这是"让爸爸有成长感"的技术落地。核心洞察：成长感 = 有参照系才能被感知。孤立的胜率数字不产生成长感，只有对比才产生。

2.1 三层参照系

时间参照          难度参照          瞬间参照
三个月前 vs 现在   难度在自动升档    和过去的自己对
      ↓                 ↓                ↓
底层数据：每一步的引擎评估 + 全部历史棋谱
（成长感的事实来源，不做任何美化）
      ↓                 ↓                ↓
可感知的进步        难度可见          被肯定的瞬间
和过去的自己下一盘  升档时明确告诉他   复盘先讲他做对的

2.2 逐条实现

① 时间参照 —— 和过去的自己下一盘

最有说服力的一条，因为"进步"只有横向对比才成立。

实现：每局结束存 FEN 全序列 + 该局实际难度参数。三个月后，"挑战三个月前的自己"会取出那盘棋谱，用当时那个难度档的引擎参数重新推演。也就是说，三个月前他赢的那盘棋，现在由"过去水平的他"来下。

  • 他赢了 → 明确提示："三个月前的你赢不了这盘，你现在赢了。"
  • 他输了 → 不显示"你输了"，显示"这盘比三个月前难一点，再来"。

不需要 AI、不需要云，纯本地数据 + 引擎已有参数体系就能实现。这是我认为最值得做的一条。

② 难度参照 —— 升档要"可见"

自动升降档本身不够，必须让爸爸知道这件事发生了。

  • 连续 3 胜 → 弹一次："你最近赢得多，我给你调难一点了。"（附难度档位变化）
  • 连续 3 负 → "这档有点难，我给你调简单点。"
  • 文案必须像朋友说话，不出现"算法调整""参数"这类词。

③ 瞬间参照 —— 复盘先讲做对的

见 §4，复盘引擎的核心设计约束。

2.3 进步可视化：用真实数据算，不编

需要一个"我的棋力"指标。不能拍脑袋编一个分，要基于引擎真实评估来算：

  • 每局结束时，引擎已经给出双方每步的评估分
  • 统计他有多少步与引擎首选着一致（命中率）
  • 用这个命中率 + 胜率 + 当前档位，换算成中国象棋段位（1-9 段是中式象棋 culturally 熟悉的刻度，比 Elo 更好懂）

好处：段位是中国象棋玩家天然懂的单位，"3 段"比"Elo 1450"有感得多。数据来源是引擎真实评估，不是伪造。

3. 我建议加的 6 个点子（你原始需求里没有的）

按"投入产出比"排序，不是按技术难度。

3.1 语音报着法与复盘朗读 ⭐ 强烈建议

为什么：爸爸看"炮二平五"这四个字没问题，但看一整屏复盘文字就费劲。耳朵比眼睛省力。

技术：Web Speech API 的 speechSynthesis（文字转语音），浏览器原生、离线、零成本。

实测结论：

  • ✅ 安卓 Chrome 完全支持，中文（lang: 'zh-CN'）正常
  • ✅ 走子时播报"炮二平五"，复盘时朗读点评
  • ⚠️ Android WebView 里可能静默失败（不报错也不响）——必须做兜底：启动时探测能力，不支持就隐藏语音按钮，并提示"当前设备不支持语音提示"，其余功能全部照常
  • 语速建议 0.9x（老人听太快跟不上）

投入：小（几十行代码 + 兜底）。感知强。

3.2 每日一题残局 ⭐ 强烈建议

为什么：这是唯一能让爸爸主动打开 App 的理由。跟电脑下棋是"消耗时间"，每日一题是"有收获"。而且残局是真正提升棋力最快的地方。

技术：不用外部题库。用引擎自己生成——从棋谱里截取一个"能将军死"的局面，问"红方怎么走能绝杀"。引擎能验证答案对错。

形式：每天一题，做完给一句点评。连续做有连续天数（简单计数器）。

投入：中。留存价值最高的一条。

3.3 进步可视化（段位） ⭐ 建议

见 §2.3。"我现在是几段"是老人和棋友聊天时最自然的单位。

3.4 中断续局不丢棋 ⭐ 建议

为什么：下到一半接个电话、孙子来找他玩，回来发现棋没了——这种挫败感会直接杀死使用习惯。

技术：每落一子就把 FEN + 走子序列写进 IndexedDB。重新打开时检测到未完成对局，问"上次那局还要继续吗"。

投入：小。防流失的关键细节。

3.5 棋风个性报告 ⭐ 可选

为什么：用他自己的棋谱算出一些有意思的结论，比干巴巴的胜率有温度。

可算的指标（全部来自真实数据）：

  • 常用开局（炮二平五 / 飞相局 / 中炮对屏风马）——他最熟悉的套路
  • 平均每步思考时间（快攻型 vs 稳健型）
  • 最爱悔棋的位置（有意思）
  • 一天中哪个时段胜率最高

投入：中（数据已有，主要是文案组织）。分享价值高——可以生成一张卡片发给棋友。

3.6 护眼与久坐提醒 ⭐ 可选

为什么：老人对时间没感觉，一坐一下午。45 分钟提醒一次"起来走两步"，屏幕调暗。

投入：极小。

3.7 一个我主动砍掉的想法（但你可能想要）

"让电脑让一局"（让子棋）：对提升信心很有用。但它和"自动升降档"功能重叠——自动降档已经解决了"打不动"的问题，再加让子就是双重放水，反而让难度体系失真。

我的默认处理：不做自动让子，但做成独立模式——首屏第三个按钮"今天想赢一把"，点了才用低一档引擎且开局送一子。主动选择，不影响难度体系。

如果你更想要"每次输了自动让子"，告诉我，这个改起来也不难。

4. 复盘反馈引擎（按"给爸爸看"重新设计）

4.1 核心设计约束

约束理由
每盘只讲 1 步讲 15 个失误 = 一面墙的文字 = 直接关掉。讲 1 步 = 他会记住、会想改
先夸后批先说做对的 1 步，建立"这盘有收获"的感受，再讲 1 步该改的
绝不出现数字不出现 -35厘分、-0.3、NPS。只有"这步应该先跳马"
结尾给 1 个下一步动作"下一盘试试，开局先跳马"——让他有事可做，而不是陷入自我怀疑
术语全转人话"将军"保留（这是象棋的基本词），"双车错""海底捞月"这类术语要么不用，要么配一句解释

4.3 技术实现

必须自己写的三块：

  1. UCCI → 中文记谱转换器

底座没有这个函数（我 grep 确认过）。象棋记谱有特殊规则："炮二平五"（同一列多个炮用"前/后"）、"马8进7"（黑方用阿拉伯数字，红方用汉字）。约 150 行。

  1. 失误定位器

引擎已经输出每步的 score cp / score mate 和 MultiPV 候选着法，数据是齐的。

  • 逐步比较"你实际走的" vs "引擎首选的"
  • 用 MultiPV 拿到 top-3 候选，如果你的走法不在 top-3 且分差明显 → 标记为失误
  • 阈值要按难度档分别标定（低档位不该报太多失误，否则爸爸一看全是红字就放弃了）
  • 同时也要识别"你做对了"的步：你的走法恰好是引擎首选 → 收集起来，作为"👍"素材
  1. 人话点评生成器

模板库 + 规则填充。模板按失误类型分：

  • 漏看吃子 → "这步走过去，{子}就被吃了"
  • 应将未将 → "这里该将军，你没将，白方缓了一口气"
  • 贪吃丢子 → "这步能吃，但吃完你的马就守不住了"
  • 走子顺序问题 → "该先{建议}再{你的走法}"

为什么不上 LLM：技术上可以（平台有免密钥 LLM 调用），但每次复盘要联网 + 有 token 成本 + 结果不稳定。建议先做模板版（离线、免费、稳定、可预期），跑顺了再考虑把 LLM 作为可选增强。

4.4 一个必须注意的技术陷阱

底座 CLAUDE.md 明确记录：发给引擎的必须是 position fen <起始FEN> moves <全部着法>，不能写成 position fen <当前FEN> moves <全部着法>——后者等于在已经走完的局面上再走一遍，等于喂非法着法。

复盘引擎重走整局时必须踩准这条，否则引擎会返回垃圾评估。
