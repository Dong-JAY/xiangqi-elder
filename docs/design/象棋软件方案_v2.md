| **让爸爸有成长感** | ⚠️ **这条推翻了我 v1 的一个设计假设。** v1 写"隐藏所有引擎数据"——技术术语该藏，但**进步信号必须露出来**。见 §4 成长感系统 |

### 4 个答案里最值得说的：成长感 ≠ 隐藏数据

v1 我主张"把所有引擎数据折叠进详情页"。这对**技术参数**是对的（深度/节点/NPS 对爸爸无意义），但如果连**进步本身**也藏起来，就没有成长感了。

正确的切分是：

| 该藏 | 该露 |
|---|---|
| 深度、节点数、NPS、厘分损失 | 连胜几场、难度升到第几档、和上个月比进步了多少 |
| "score cp -35" | "这步应该先跳马" |
| 引擎内部思考过程 | "你上盘这步就对了，这次换了个思路也一样对" |

**核心原则：藏术语，露进步。**

## 2. 成长感系统（新增，v1 没有）

这是"让爸爸有成长感"的技术落地。核心洞察：**成长感 = 有参照系才能被感知**。孤立的胜率数字不产生成长感，只有对比才产生。

### 2.1 三层参照系

```
时间参照          难度参照          瞬间参照
三个月前 vs 现在   难度在自动升档    和过去的自己对
      ↓                 ↓                ↓
底层数据：每一步的引擎评估 + 全部历史棋谱
（成长感的事实来源，不做任何美化）
      ↓                 ↓                ↓
可感知的进步        难度可见          被肯定的瞬间
和过去的自己下一盘  升档时明确告诉他   复盘先讲他做对的
```

### 2.2 逐条实现

**① 时间参照 —— 和过去的自己下一盘**

最有说服力的一条，因为"进步"只有横向对比才成立。

实现：每局结束存 FEN 全序列 + 该局实际难度参数。三个月后，"挑战三个月前的自己"会取出那盘棋谱，用**当时那个难度档的引擎参数**重新推演。也就是说，三个月前他赢的那盘棋，现在由"过去水平的他"来下。

- 他赢了 → 明确提示："三个月前的你赢不了这盘，你现在赢了。"
- 他输了 → 不显示"你输了"，显示"这盘比三个月前难一点，再来"。

不需要 AI、不需要云，纯本地数据 + 引擎已有参数体系就能实现。**这是我认为最值得做的一条。**

**② 难度参照 —— 升档要"可见"**

自动升降档本身不够，必须让爸爸**知道**这件事发生了。

- 连续 3 胜 → 弹一次："你最近赢得多，我给你调难一点了。"（附难度档位变化）
- 连续 3 负 → "这档有点难，我给你调简单点。"
- 文案必须像朋友说话，不出现"算法调整""参数"这类词。

**③ 瞬间参照 —— 复盘先讲做对的**

见 §4，复盘引擎的核心设计约束。

### 2.3 进步可视化：用真实数据算，不编

需要一个"我的棋力"指标。**不能拍脑袋编一个分**，要基于引擎真实评估来算：

- 每局结束时，引擎已经给出双方每步的评估分
- 统计他有多少步与引擎首选着一致（命中率）
- 用这个命中率 + 胜率 + 当前档位，换算成**中国象棋段位**（1-9 段是中式象棋 culturally 熟悉的刻度，比 Elo 更好懂）

好处：段位是中国象棋玩家天然懂的单位，"3 段"比"Elo 1450"有感得多。数据来源是引擎真实评估，不是伪造。

## 3. 我建议加的 6 个点子（你原始需求里没有的）

按"投入产出比"排序，不是按技术难度。

### 3.1 语音报着法与复盘朗读 ⭐ 强烈建议

**为什么**：爸爸看"炮二平五"这四个字没问题，但看一整屏复盘文字就费劲。**耳朵比眼睛省力**。

**技术**：Web Speech API 的 `speechSynthesis`（文字转语音），浏览器原生、离线、零成本。

**实测结论**：
- ✅ 安卓 Chrome 完全支持，中文（`lang: 'zh-CN'`）正常
- ✅ 走子时播报"炮二平五"，复盘时朗读点评
- ⚠️ **Android WebView 里可能静默失败**（不报错也不响）——必须做兜底：启动时探测能力，不支持就隐藏语音按钮，并提示"当前设备不支持语音提示"，**其余功能全部照常**
- 语速建议 0.9x（老人听太快跟不上）

**投入**：小（几十行代码 + 兜底）。**感知强**。

### 3.2 每日一题残局 ⭐ 强烈建议

**为什么**：这是**唯一能让爸爸主动打开 App 的理由**。跟电脑下棋是"消耗时间"，每日一题是"有收获"。而且残局是真正提升棋力最快的地方。

**技术**：不用外部题库。用引擎自己生成——从棋谱里截取一个"能将军死"的局面，问"红方怎么走能绝杀"。引擎能验证答案对错。

**形式**：每天一题，做完给一句点评。连续做有连续天数（简单计数器）。

**投入**：中。**留存价值最高的一条**。

### 3.3 进步可视化（段位） ⭐ 建议

见 §2.3。"我现在是几段"是老人和棋友聊天时最自然的单位。

### 3.4 中断续局不丢棋 ⭐ 建议

**为什么**：下到一半接个电话、孙子来找他玩，回来发现棋没了——**这种挫败感会直接杀死使用习惯**。

**技术**：每落一子就把 FEN + 走子序列写进 IndexedDB。重新打开时检测到未完成对局，问"上次那局还要继续吗"。

**投入**：小。**防流失的关键细节**。

### 3.5 棋风个性报告 ⭐ 可选

**为什么**：用他自己的棋谱算出一些有意思的结论，比干巴巴的胜率有温度。

可算的指标（全部来自真实数据）：
- 常用开局（炮二平五 / 飞相局 / 中炮对屏风马）——他最熟悉的套路
- 平均每步思考时间（快攻型 vs 稳健型）
- 最爱悔棋的位置（有意思）
- 一天中哪个时段胜率最高

**投入**：中（数据已有，主要是文案组织）。**分享价值高**——可以生成一张卡片发给棋友。

### 3.6 护眼与久坐提醒 ⭐ 可选

**为什么**：老人对时间没感觉，一坐一下午。45 分钟提醒一次"起来走两步"，屏幕调暗。

**投入**：极小。

---

### 3.7 一个我主动砍掉的想法（但你可能想要）

**"让电脑让一局"**（让子棋）：对提升信心很有用。**但它和"自动升降档"功能重叠**——自动降档已经解决了"打不动"的问题，再加让子就是双重放水，反而让难度体系失真。

**我的默认处理**：不做自动让子，但做成**独立模式**——首屏第三个按钮"今天想赢一把"，点了才用低一档引擎且开局送一子。主动选择，不影响难度体系。

如果你更想要"每次输了自动让子"，告诉我，这个改起来也不难。

## 4. 复盘反馈引擎（按"给爸爸看"重新设计）

### 4.1 核心设计约束

| 约束 | 理由 |
|---|---|
| **每盘只讲 1 步** | 讲 15 个失误 = 一面墙的文字 = 直接关掉。讲 1 步 = 他会记住、会想改 |
| **先夸后批** | 先说做对的 1 步，建立"这盘有收获"的感受，再讲 1 步该改的 |
| **绝不出现数字** | 不出现 -35厘分、-0.3、NPS。只有"这步应该先跳马" |
| **结尾给 1 个下一步动作** | "下一盘试试，开局先跳马"——让他有事可做，而不是陷入自我怀疑 |
| **术语全转人话** | "将军"保留（这是象棋的基本词），"双车错""海底捞月"这类术语要么不用，要么配一句解释 |

### 4.2 输出样例（这是我要交付的东西，不是设想）

```
┌─────────────────────────────────────┐
│  这盘你赢了                        │
│                                     │
│  👍 第 12 步你跳马过兵              │
│     这步很主动，把黑方的车堵住了    │
│                                     │
│  👉 第 27 步可以更好                │
│     当时应该炮五进七，你走的炮二平五 │
│     少了一个子，所以后面很被动      │
│                                     │
│  💡 下一盘试试：开局先跳马，别急着出炮│
│                                     │
│  再来一局 →                          │
└─────────────────────────────────────┘
```

### 4.3 技术实现

**必须自己写的三块**：

1. **UCCI → 中文记谱转换器**
   底座**没有**这个函数（我 grep 确认过）。象棋记谱有特殊规则："炮二平五"（同一列多个炮用"前/后"）、"马8进7"（黑方用阿拉伯数字，红方用汉字）。约 150 行。

2. **失误定位器**
   引擎已经输出每步的 `score cp` / `score mate` 和 MultiPV 候选着法，数据是齐的。
   - 逐步比较"你实际走的" vs "引擎首选的"
   - 用 MultiPV 拿到 top-3 候选，如果你的走法不在 top-3 且分差明显 → 标记为失误
   - 阈值要按难度档分别标定（**低档位不该报太多失误**，否则爸爸一看全是红字就放弃了）
   - **同时也要识别"你做对了"的步**：你的走法恰好是引擎首选 → 收集起来，作为"👍"素材

3. **人话点评生成器**
   模板库 + 规则填充。模板按失误类型分：
   - 漏看吃子 → "这步走过去，{子}就被吃了"
   - 应将未将 → "这里该将军，你没将，白方缓了一口气"
   - 贪吃丢子 → "这步能吃，但吃完你的马就守不住了"
   - 走子顺序问题 → "该先{建议}再{你的走法}"

**为什么不上 LLM**：技术上可以（平台有免密钥 LLM 调用），但每次复盘要联网 + 有 token 成本 + 结果不稳定。**建议先做模板版**（离线、免费、稳定、可预期），跑顺了再考虑把 LLM 作为可选增强。

### 4.4 一个必须注意的技术陷阱

底座 CLAUDE.md 明确记录：**发给引擎的必须是 `position fen <起始FEN> moves <全部着法>`，不能写成 `position fen <当前FEN> moves <全部着法>`**——后者等于在已经走完的局面上再走一遍，等于喂非法着法。

复盘引擎重走整局时**必须踩准这条**，否则引擎会返回垃圾评估。

## 5. 适老化改造（第一优先级）

底座是给开发者看的 UI，我们要给老人用。

| 维度 | 底座原样 | 我们改成 |
|---|---|---|
| 布局 | 桌面横屏，600px 棋盘 + 560px 侧栏 | **竖屏单列**，棋盘占满屏宽，引擎数据全折叠进详情页 |
| 配色 | 深色科技面板 `#20242b` | **浅色高对比**（老人对深色+小字识别率明显低）|
| 字号 | 桌面级 | 正文 ≥ 20px，按钮 ≥ 56px 高 |
| 首屏 | 多层嵌套菜单（开始→模式→先手） | **首屏 3 个大按钮**：和电脑下 / 挑战过去的自己 / 我的成绩 |
| 先手 | 每次都问 | 默认随机（或沿用上次），不打扰 |
| 术语 | 深度/节点/NPS/评估分 | 全藏进"详情"。主界面只说人话 |
| 着法 | `h2e2` | `炮二平五` |
| 落子反馈 | 提示点 | 保留 + **触觉震动 + 落子音效** |
| 声音 | 无 | 走子语音播报（可选，见 §3.1）|
| 结束语 | "红方胜！"| "这局你赢了" / "这局电脑赢了，再来一盘" |
| 失败后 | 弹窗 | **直接进复盘**，不问他要不要看 |

**移动端是最大未知数**——底座作者自己标注了"移动端未实测"。风险点在 `pikafish-engine.js` 里的硬编码假设。**必须在你爸的真机上跑一轮**，模拟器不算。

### 存储设计（IndexedDB，3 个 store）

| Store | 内容 | 用途 |
|---|---|---|
| `games` | 每局：时间/难度/执子/结果/手数/FEN 序列 | 战绩统计、复盘重演 |
| `current` | 当前未完成对局 | 中断续局 |
| `meta` | 段位、连胜、连续天数、做过的每日一题 | 成长感系统 |

**导出兜底**：设置里给一个"导出我的战绩"按钮，生成 JSON 文件让爸爸存到微信收藏/发给自己。浏览器清缓存也不怕。

## 7. 实施阶段

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **P0 地基** | fork 底座 → 本地跑通 → 部署 | 6 档均可玩，PC 端无 console 报错 |
| **P1 适老化**（最重要）| 竖屏布局、浅色大字、人话文案、中文着法、首屏 3 按钮 | **在爸爸真机上**完整走完一局，看得清点得准 |
| **P2 战绩 + PWA** | IndexedDB 3 store、成绩页、manifest+sw、导出 | 关浏览器重开数据还在；能添加到主屏幕；断网能玩档 1-3 |
| **P3 复盘引擎** | 记谱转换 + 失误定位 + 教练点评卡 | 复盘能准确指出"这步该走什么"，语气读起来像鼓励不像批改 |
| **P4 成长感** | 段位计算 + 升档可见 + 挑战过去的自己 | 能玩"三个月前的自己"，提示语自然 |
| **P5 每日一题 + 打磨** | 残局生成、语音播报、久坐提醒、音效 | 爸爸连续用 1 周，有主动打开的意愿 |

**节奏建议**：P0+P1 先做出来给爸爸试用 3-5 天，收他的真实反馈（哪里点不动、看不清、听不懂），再定 P3 复盘的具体话术。**不要一口气做完再给他**——适老化只能靠真实用户迭代出来。

## 9. 还差 3 个决定

1. **是否公开发布**？（涉 GPL-3.0 传染：只自用没问题；公开/上架则整个项目须开源）
2. **复盘点评是否接 LLM**？（我的建议：先做模板版，跑顺后再考虑）
3. **"让一局"要不要**？（我的建议：做成独立模式"今天想赢一把"，不做自动让子）
